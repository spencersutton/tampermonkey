# tampermonkey

## Triangle Liquidators – Hide, Filter & Bid Confirm

A separate, faster catalog for [triangleliquidators.com](https://triangleliquidators.com/), run as a web app (phones included) from a small server you run yourself.

- **Every live lot, held in the page.** Filtering and sorting run locally, so they make no requests.
- **Lot cards** are compact: condition and location on one line above the title; brand and model on one line when provided; category, item type and tags in one row; then the current bid, estimated total and bid button on one line, with time left, bids and retail (and the bid as a % of it) beneath. Hover a figure for its details (cost breakdown, retail share). Model numbers link to a search for the brand and model, just like in the popup. The layout wraps on narrow screens.
  Brands and models already in the server's saved lot details arrive with the catalog, including after a refresh or on another device. For uncached items, both load automatically as cards approach the viewport, two shared detail requests at a time, without opening the lot. Items known to have no brand or model are not fetched again just for those fields. Failed detail loads offer a retry on the card.
  Click the category name to show only lots assigned to that category, keeping other filters unchanged. This selects the displayed category only, not its subcategories (a parent's directly assigned lots are its “Other” row).
  Click the hide icon beside the category name to uncheck that category in the sidebar without changing other filters or individually hiding lots. This affects the displayed category only, not its subcategories. With no category filter, it selects all other categories; hiding the last selected category shows no results. Check a category, choose “Show all categories”, or Clear to resume browsing. The selection is retained on reload, in shared URLs, and in saved searches and defaults.
- **Sort** by best match (the default: search relevance, then ending soonest; with no search it is ending soonest), ending time, newly listed, title (A–Z / Z–A, grouped by item type, leading specs moved to the end), brand + model (A–Z, natural model-number order, falling back to title when either field is missing), estimated total cost, % of retail, retail price, or random (a fresh shuffle each page load that holds still as lots update).
- **Item types:** the server names what each lot is (“pressure washer”, “area rug”) with an LLM, shown as a chip on each card. Click the chip to show only lots of that type; click the **+** beside it to create a category of that type, with a suggested name, parent selector, and similar types to include. In “New category”, Parent defaults to the lot's current custom category (if any) or its site category, and Name defaults to the pluralized item type. The parent is retained even if its last item type moves to the child. “Add to existing” defaults to the last category used or created in this browser, with nearby categories listed first; search by name or path to filter the list. See _Item types_ under the server below for setup.
  Use the pencil beside the item type on a card or in its details to correct it, or “Set item type” if none is assigned. Pick an existing type from the suggestions or enter a short singular name. It saves in lowercase, updates sorting and category matching immediately, and applies to listings with the same brand and model, including future relistings. If either listing lacks brand or model, it falls back to the exact title. Corrections live on the server and automatic labelling cannot replace them. Existing title-only labels remain usable.
- **Search like a shop:** as you type, a dropdown suggests matching item types, brands and categories (with lot counts), plus the best-matching lots with thumbnail and price. Picking an item type, brand or category filters by it and clears the text; picking a lot opens it; Enter searches right away. With the box empty, it lists your recent searches (kept in this browser). Use ↑/↓ to move, Enter to pick, Esc to close, and press **/** anywhere outside a text field to jump to the search box.
  Results are ranked by relevance under _Best match_: a word matching the item type or brand counts more than one in the title, a whole word more than part of one, and the words together as a phrase more still. Plurals and singulars match each other (“drills” finds “drill”, “battery” finds “batteries”), and common shopper synonyms do too (“fridge” finds “refrigerator”, “weed eater” finds “string trimmer”). One- and two-letter words must start a word. Put `-` before a word to exclude it (`drill -bit`). If a search matches nothing, misspelt words are corrected to the closest words in the catalog and those results are shown, with a note saying so. Matched words are bold in card titles.
  Above the grid, each active filter is a removable chip (with “Clear all”), the item types among the results are listed as one-click refinements, and a _Brand ▾_ dropdown (shown when the results have more than one brand) lists their brands with counts; tick brands to filter, or type in its box to find one.
- **Tags:** a lot can have any number of tags besides its item type. A plain tag (“cabinet knob”) is a label; a `name: value` tag (“finish: satin nickel”) is an attribute. Above the grid, each attribute name found among the current results gets a dropdown (“Finish ▾”, “Size ▾”, with plain tags under “Tags ▾”) listing its values with counts; tick values to filter. Values of one attribute are alternatives (satin nickel _or_ brass), while different attributes and plain tags must all match. Counts work like the sidebar's: each dropdown ignores its own selection. Tags show on cards (click one to filter by it), appear in the search suggestions, are searchable as plain words, and `tag:` restricts a word to them (`tag:nickel`). Tags are set on the server, per lot or by title rules; see _Tags_ under the server below.
- **Filters:** search, category, item type, brand, tags, condition, location, "available at my pickup location", bid / total / retail ranges, ending window, and _my lots_ (bid on / winning / outbid / watchlist; picking one clears the other filters and also shows hidden and regex-filtered lots).
  Filter counts follow the current results, as on a shopping site: each list counts the lots matching everything else, ignoring its own selection, so you can still add a second brand or condition. Options with no results are dimmed. _Item type_ and _Brand_ list the most common first, with “Show more” and a box to find the rest; brands ignore case and spacing (“DEWALT” and “DeWalt” are one brand). _Price_ has one-click current-bid ranges with counts.
  Search matches title, lot number, item type, and known brand/model details, even when those details are absent from the title. Use `brand:dewalt model:dcd791` to restrict terms to those fields, `type:"pressure washer"` for the item type, or `brand: "Black & Decker" drill` for a multi-word brand plus a general term. Matching is case-insensitive, allows partial values, and requires every term to match; quoted phrases stay together. The same rules apply to saved searches and shared URLs. Regex mode searches all five fields as text and does not interpret qualifiers, `-`, stemming or synonyms. Brand/model matching uses details already cached or loaded, including server-cached details for off-screen lots; searching does not fetch unknown details for every lot.
  Click a brand on a card or in the lot popup to search the catalog for that brand; click a model to search for both its brand and model (or just the model when no brand is known). These links clear the current filters and keep your sort. The separate Google icon searches the web for the brand and model in a new tab.
  Use “Expand all” or “Collapse all” under _Category_ to open or close every level without changing selections, or press **Alt+Shift+E** / **Alt+Shift+C**. Expanding also opens the Category section if it was closed. Click the focus icon (a dot inside four corners, with a “Show only…” tooltip) beside a category to show only that category (including its subcategories for a parent), clearing every other filter: search, brand, tags, condition, location, prices and the rest (the sort stays). The focus icon beside a parent's “Other” row selects just its directly assigned lots. Checkboxes still add or remove categories without touching other filters.
- **Keyboard shortcuts:** press **?** (**Shift+/**) outside a text field, or click “Keyboard shortcuts (?)” in the sidebar, to open the guide. It lists jumping to search (**/**), saving defaults, expanding/collapsing categories, and closing popups with **Esc**. On Mac, use **Option** instead of **Alt**. Catalog shortcuts are inactive while a popup is open.
- **Default filters:** select categories and conditions, then use “Save category & condition defaults” under the filters or press **Alt+Shift+D** (**Option+Shift+D** on Mac). The shortcut is inactive while a popup is open. Clear restores those selections and clears the other filters while keeping the sort. To remove the defaults, uncheck all categories and conditions and save again (use “Show all categories” first if hiding the last category left no results). Defaults sync across devices and apply when a browser has no saved view; an existing view or a shared URL takes precedence.
- **Custom categories:** under _Category_, “Add / Edit custom categories” opens the hierarchical editor. Edit category names, parent category, and item types directly in each row, add top-level categories or subcategories with **+**, and delete categories (children move up a level when a parent is deleted). Categories are grouped under their parent site or custom category and sorted alphabetically at each level; duplicate names are allowed under different parents. A parent with children may be a group with no item types of its own and is retained when its last item type moves to a new child. Legacy “Parent - Name” categories are migrated automatically while preserving existing filters and saved searches. Changes apply on Save.
  Categories match exact item types across all site categories; the first matching category alphabetically wins. Previously saved site restrictions are ignored, so lots may move to a different category. Previously saved title regexes no longer match, so add item types to any affected categories. In the filter, parents expand independently and select their whole branch; “Other” selects only directly assigned lots.
- **Duplicate listings combined:** listings of the same item at any location show as one card with a “+N more” badge; the popup lists them all, with each one's condition when they differ. Listings with exactly the same brand and model combine in any condition; title-matched listings combine only within one condition. The card shows the best condition (New, then Like New, Used, As-is), the cheapest total cost within it (lots you can't get to your pickup location come last). If a worse condition costs less, the card adds a note such as “Used for ≈ $9 total (save $4)”; click it to open that listing. When both listings have brand and model, those fields determine the match regardless of title. Matching ignores case and extra whitespace but keeps model punctuation and word order significant. Different known brands/models never combine, even through a third listing with missing details. If either listing lacks brand or model, titles must share 90% of words, ignoring case, punctuation and order. In that title fallback, a number only one title has (a size, pack count or “Qty 4”) never matches. The server does the matching across the whole catalog, so grouping doesn't depend on your filters, and it regroups shortly after newly fetched details arrive; searching and matching do not fetch all unknown details.
- **Past closing prices:** each card says what matching items (using the same brand/model-first rule and title fallback) sold for before, e.g. “Sold before for $12 (median of 4)”, counting only those in the same condition when there are any; hover for the recent ones. The popup lists every past close with its condition, location, bids and date. Saved details remain available after closing and identity changes refresh the comparisons. Starts empty and fills as lots close (see _Closed lots_ below).
- **Hide lots and regex filters** (case-insensitive, whole-word: `\b(?:pattern)\b` against the title; a pattern that matches a lot's entire item type, e.g. `pressure washer`, filters it too). Filters are listed one per line with how many lots each matches; click a pattern to edit it (Enter saves, Esc cancels).
- **Saved searches:** save the current filters and search, then see at a glance how many matching lots were listed since you last opened each one (also shown in the tab title, e.g. “(3) TL Catalog”). After changing the search, filters, or sort, click “Update” beside a saved search to replace its settings without changing its name or last-viewed time; “Save current” still creates a separate search. The temporary “Show only new” setting is not saved. Opening a search badges the new lots; “Show only new” narrows to them. Hidden and regex-filtered lots never count. A lot is new if it first appears in a full catalog refresh, so new listings show up within one refresh interval.
- **New badges everywhere:** outside a saved search, every lot listed since your previous visit gets a _New_ badge, with a count and “Show only new” above the grid. A visit starts when the app loads, or when you come back to its tab after 30 minutes away; it's shared by all your devices. The first time, lots with more than 2 days left count as new.
- **Live prices** for the lots on screen over the site's own websocket, plus outbid/winning updates when logged in.
- **Infinite scrolling:** the grid shows 60 lots and adds 60 more each time you scroll near the end.
- **Lot details** (images, description, bid history) in a popup, with the site's _Similar auctions_ that are still open along the bottom (a lot in the catalog opens in the popup, any other on the site).
  Saved descriptions, brand/model, lot fees and full image lists are reused from the server, including after reloads and for closed lots. The popup shows saved item details while refreshing auction data; stored prices, bids, standings and watchlist state are never served as fresh metadata. New lot versions, bids and login changes invalidate the short-lived auction-detail cache without discarding item metadata. The site's detail response still includes both kinds of data, so a live refresh also updates the saved metadata.
- **Won / Lost pages:** _Closed: Won · Lost_ under _my lots_ shows the lots you won or lost, as the site's control panel lists them (the site keeps lost lots for 14 days), with each one's final price; for won lots also the estimated total with premium, lot fee and tax, and the sum. A filter box narrows the list. Click a lot for its details in the popup. Matching items listed again (brand/model first, with title fallback when either side lacks complete details) show as “N listings open now”, which opens the list of them, cheapest total first.
- **Condition descriptions:** hover a condition (filter, card or popup) for the site's description of it, or open _About conditions_ under the Condition filter.
- **Shareable URLs:** the view lives in the address, e.g. `/tlx?search=dewalt&sort=price-low&category=tools&page=2&lot=123` (only non-default values appear; filters are `category`, `noCategories`, `type`, `brand` (lowercase), `tag` (e.g. `tag=finish:+satin+nickel`, any case; `tag=finish:` is the dropdown's “None”), `condition`, `location`, `reachable`, `priceMin`, `priceMax`, `totalMax`, `retailMin`, `ending`, `mine`; `noCategories=1` explicitly shows no categories; `closed=won` or `closed=lost` shows that page). `page=N` means N batches of 60 lots were scrolled in. Opening such a URL loads that search, that many lots and the lot.
- **Back / forward buttons** step through filter, sort and search changes and opened lots, putting back the scroll position and the lots scrolled in so far (scrolling in more lots doesn't add an entry). Back closes an open lot popup; typing in the search box makes one history entry, not one per keystroke.
- **Watchlist:** star a lot on its card or in the popup to add or remove it from your site watchlist (the “Watchlist” filter under _my lots_ shows them). As on the site, lots you've bid on no longer show a watchlist star or appear in the Watchlist filter; find them under _Lots I bid on_, _I’m winning_, or _I’m outbid_ instead.
- **Bidding** without leaving the app: a quick “Bid $N” (next increment) button on each card, and quick bid or max bid (or raise your max while winning) in the lot popup. Every bid asks to confirm first, showing the estimated total cost if you win and a warning when the lot is pickup-only elsewhere or needs a transfer. If the price moves while the confirmation is open, it won't send an amount the site would now reject. Bidding is disabled for hidden and filtered lots, closed lots, and when you're not logged in. Bids use the same request as the site's own bid buttons (`POST /v1/auctions/lots/{id}/bids`).

**Server load:** the full catalog (~50 requests) is pulled at most once per interval (default 5 minutes, configurable under Settings down to 1 minute). The interval is measured from the start of the last pull, failed or not. Pulls only run while an app tab is visible and has been used in the last 10 minutes. Pages are fetched one at a time. Opening a lot fetches only that lot (cached 2 minutes). Live updates subscribe only to the lots on screen, like the site does.

### Running the server

The app is served by a small server you run yourself (`src/server/`, TypeScript on [Bun](https://bun.sh) with [Hono](https://hono.dev)). It works in any browser, phones included; "Add to Home Screen" gives it an app icon.

It needs Node (for npm); `npm install` also installs Bun. Build the web app once first, and again after pulling changes to `src/` or `web/`:

```bash
npm install && npm run build
```

Run `npm test` for the regression tests.

### Client structure

The client uses Preact for rendering and signals for shared state and derived
views. One-shot startup waits for the first unlocked session. DOM setup and
cleanup belong to element refs; effects remain for ongoing synchronization and
data loading. Dialog refs are stable per instance, so opening a bid confirmation
above a lot never closes the underlying popup. Lot dialogs keep their outer dialog mounted while keyed contents
reset when switching lots, so image selection, details and scroll position do
not leak between listings.

Catalog replies merge in one place: newer live prices win, server metadata stays
authoritative, and pending item-type corrections survive older in-flight polls.

### Starting the server

```bash
npm run server                                            # this computer only: http://127.0.0.1:8765
TLX_PASSWORD='pick-one' npm run server -- --host 0.0.0.0  # also your phone: http://<computer's address>:8765
npm run server -- --help                                  # --port, --db, --llm-key, --tls-cert/--tls-key, ...
```

The server stores its data in PostgreSQL (default `postgres://localhost:5432/tlx`, override with `--db`, `TLX_DB`, or `DATABASE_URL`). To migrate an existing SQLite database into PostgreSQL, run `bun scripts/migrate-sqlite.ts` (pass `--truncate` to replace existing rows).

The app can't call the site directly, because the site's API doesn't allow other origins and its websocket only accepts its own pages. So the server stands in for the site:

- **Your login.** Use _Log in_ (in the banner, the lot popup, or _Settings_) to have the server sign in to Triangle Liquidators. Your password is sent to the site once and isn't stored. The server keeps the site's session cookies, so you stay logged in, and refreshes the API token as needed. _Log out_ signs the server out.
- **The site's API.** Lot details, bids and the watchlist go through the server at `/backend/...`, with your token added. A rejected token is refreshed and the request retried once, as the site's own client does.
- **Live prices.** The server relays the site's websocket message for message, presenting itself with the site's Origin.
- **The catalog.** The server pulls the catalog and stores it in PostgreSQL, with the load rules above: at most once per interval, measured from the start of the last pull, and pages fetched one at a time. It pulls whether or not an app is open, so saved searches keep counting new lots. Each tab fetches only what changed since its last check, about every 15 seconds.
- **Item types.** With an API key for an OpenAI-compatible LLM (`--llm-key` or `TLX_LLM_KEY`), the server names each new item's type after every pull, in batches of 40 titles from one site category with the types that category already uses, so the same kind of item gets the same name. Types are reused by brand/model with exact-title fallback when either side lacks a complete identity; each known identity needs only one label request. The default is Ministral 3 14B on [nano-gpt.com](https://nano-gpt.com) (`--llm-url`, `--llm-model` or `TLX_LLM_URL`, `TLX_LLM_MODEL` to change it); labelling the whole catalog once costs a few cents. Without a key lots have no automatic item type, and everything else works as before.
- **Tags.** Stored in `item_tags` the same way as item types: by brand/model when both are known, else by exact title, so relistings keep them. They are tidied on save (single spaces, `name: value` for attributes) but keep their case: “Finish: Satin Nickel” shows as written, while every comparison (filters, counts, repeats, the URL) ignores case, so “finish: satin nickel” is the same tag and the dropdowns show each tag in its most common spelling. Tags set by hand are marked manual, so a future automatic tagger won't replace them. **Tag rules** (`tag_rules`) give tags to every lot whose title matches a regular expression (JavaScript syntax, case-insensitive, anywhere in the title), including lots in future pulls. A rule's tag can use what the pattern captured: `$1`, `$2`… for numbered groups, `${name}` for `(?<name>…)`, `$0` for the whole match and `$$` for a dollar sign, so pattern `(satin nickel|brass|chrome)` with tag `finish: $1` gives each lot the finish its title names, spelled as in the title; a tag whose group captured nothing is skipped, and a reference to a group the pattern lacks is refused. Manage them on the server's **/tags** page (also linked at the bottom of the catalog's sidebar; `/tags.html` under `npm run dev`): a full-screen editor with the rules on one side and, on the other, the rule being written with a live preview of the current lots it matches, the matched text marked and the tags it would add (groups filled in) shown. A lot's tags are its own plus those of every matching rule, without repeats; Open app tabs pick changes up on their next check.
- **Closed lots.** When a lot leaves the catalog, the server keeps a small row of it (title, price, bids, condition, location; about 200 bytes, so well under 100 MB a year) and, after the pull, asks the site once for its final price and whether it sold, one lot at a time with a short pause between. Lots get most of their bids in the last minutes, so the last price a pull saw is often low; a popup marks with * any price the site couldn't confirm. Closed lots are kept for good.
- **Server-only settings.** Hidden lots, regex filters, custom categories, default category and condition filters, saved searches, your pickup location and the refresh interval are stored only on the server. Each page load reads them from the server, and edits are saved directly through the API; failed saves show an error. Old browser copies are ignored and never uploaded. A missing server setting uses its default. Reload the browser page to see edits from another device or direct database changes; the catalog's Refresh button only refreshes lots.
  The current view, collapsed panels and other browser-only UI preferences remain in localStorage. Shared settings are held only in memory while the page is open.

**Security.** The server is logged in as you and can bid, so treat it like a password:

- **Password.** Listening anywhere but this computer requires `--password` (or `TLX_PASSWORD`). Each device enters it once and gets a 90-day session cookie (`HttpOnly`, `SameSite=Strict`). _Lock app_ in _Settings_ forgets it on that device.
- **Other websites.** State-changing requests must carry a header that other websites can't add, and websocket connections must come from the app's own address. Without a password, only `localhost` addresses are accepted.
- **Encryption.** On your home Wi‑Fi the connection is plain HTTP. For HTTPS, either pass `--tls-cert`/`--tls-key`, or put it behind something like `tailscale serve`, which also reaches it away from home. The server honors `X-Forwarded-Proto: https` from such a proxy.
- **Data.** The PostgreSQL database (default `postgres://localhost:5432/tlx`) holds the catalog, closed lots, item types, globally filtered item types (`filter_types`), hidden lots (`hidden_lots`), settings and the site session. Each lot is a row of `lots`, with its category, condition and location in lookup tables, its images in `lot_images` and its recent past closes in `lot_past_closes` (pointing at `closed_lots`) and its duplicate-listing group in `group_id`; its item type comes from `item_types` by brand/model, with exact-title fallback to saved labels when either identity is missing. The last detail the server fetched for each lot (when fetching a card's brand, opening its popup, or asking for a closed lot's final price) is kept in `lot_details`: description (with leading `Quantity: N,` stripped into `quantity` and trailing `Lot Number:`/`Brand:` boilerplate removed), brand, model, lot fee, images and bid history (JSON), with `fetched_at`; it stays after the lot closes and supplies identity for past prices and Won/Lost relisting suggestions. `/api/lot-metadata` serves only reusable item metadata from that table, without an upstream request.

### Development

Source is in `src/`: the web app (TypeScript + Preact, bundled with Vite) and
the server (TypeScript on Bun). The web app builds to `dist/`, which git ignores
and the server serves.

```bash
npm install
npm run build     # lint, typecheck, then build the web app
npm run typecheck # check TypeScript and included JavaScript with strict compiler options
npm run lint      # Oxlint with type-aware checks for unnecessary conditions and optional chaining
npm run dev       # web app with hot reload; API calls go to a tlx server on 127.0.0.1:8765
npm test          # web tests (node --test) and server tests (bun test)
npm run server    # the server (see above)
npm run watch     # rebuild the web app and restart the server whenever the code changes; server options go after `--`
```

`tests/fixtures/site/` holds real replies from triangleliquidators.com (public, anonymous endpoints only, captured by `scripts/capture-site-fixtures.ts`): catalog pages, lot details, errors, next-auth's logged-out replies, and a few minutes of websocket frames. `tests/site-fixtures.test.mjs` checks them against the shapes the code declares, so after a refresh a failing test means the site changed. Lot channels only publish when someone bids, so if the capture records no publication, run it again closer to closing time with `--ws-seconds=600`.

The type check also validates declaration files and enables additional checks for
optional properties, indexed access, unused code, and control flow.

Oxlint excludes files under `tests/`.

- `src/web.tsx` and `web/`: the web app entry, page and icons.
- `src/app/`: the catalog app, split into three one-way layers:
  - `src/app/logic/`: pure logic (filtering, sorting, search suggestions, bid rules, category trees/edits, closed-lot grouping, URL/history mapping, catalog merging) with no Preact, signals, DOM, or network dependencies.
  - `src/app/server/`: server HTTP/WebSocket transport (`api.ts`, `auth.ts`, `source.ts`, `live.ts`, `brands.ts`, `closed.ts`, `conditions.ts`, `bid.ts`, `watch.ts`) and reactive data stores (`catalog.ts`, `settings.ts`, `toast.ts`, `categories.ts`, `reactive.ts`) with no Preact/UI dependencies.
  - `src/app/ui/`: Preact components, UI state (`state.ts`), browser history (`history.ts`), viewport observer (`viewport.ts`), and DOM helpers (`dom.ts`).
- `src/tags/` and `web/tags.html`: the tag rules page (`/tags`), similarly split into `logic.ts` (pure), `api.ts` and `state.ts` (server/state), and `TagRulesPage.tsx` (UI).
- `src/shared/`: filters, the search engine (`search.ts`: query parsing, ranking, stemming, synonyms, spelling correction), cost formula, title sort key, item identity and settings keys, the site's raw lot normalizer (`lot.ts`), and item matching (`identity.ts`: duplicate listings, relisted items, past prices, run by the server).
- `src/server/`: the server: `main.ts` command line, `app.ts` HTTP (guards, the API, the `/backend` proxy, static files), `site.ts` the site's API client, `session.ts` site login, `relay.ts` websocket relay, `catalog.ts` pulls, `history.ts` closed lots and past prices, `itemtypes.ts` item types, and `store.ts` PostgreSQL. Type-checked with its own `tsconfig.json` (Bun, no DOM); tests in `tests/server/` (using isolated schemas in `tlx_test`).
